## Objective

Complete the five-bot 3v3 vertical slice: deterministic difficulty/rule logic, programmatic control, multi-level navigation, bounded perception and pickup memory, dynamic football roles, rocket/dash/shotgun combat, enemy difficulty setup, and pause display. Completion ends after source freeze, the one authorized production preparation/bake, one authoritative generated build, relevant EditMode tests, generated-output acceptance, and separate-process semantic validation. The user's single five-minute playtest follows this automated handoff; there is no mid-run playtest gate.

## Scope

- in: B1-B6 bots and difficulty; consumer-owned intent APIs; bot-only aim; deterministic pure rules/tests; builder-authored navigation graph; serialized sensing/role composition; generated Player prefab/MovementLab scene; setup and pause screens; final production proof.
- out: A6 shotgun inventory HUD and hit marker; multiplayer/networking, combat-assist scoring, audio/dry-fire sound, right-hand weapon replacement framework, NavMesh/package changes, hidden pickup respawn knowledge, difficulty-based health/damage/speed/cooldown/pickup changes, production UI framework/refactor, new bot markers, broad visual polish, and any earlier completed A1-A5 shotgun redesign.

## Decisions

- assumption: observed clean baseline is branch `shotgun_design_and_match_foundation` at `68d3c9f2002e68c6d2db7ff1f1d94816c3c704bf`; implementation preserves unrelated later user changes if execution starts from a different explicitly accepted SHA.
- decision: keep `PlayerInputReader` device-only. Add one-fixed-step programmatic requests to `PlayerMotor`, `BallKick`, and `RocketLauncher`; retain the existing `ShotgunWeapon.RequestFire`. Each consumer validates, consumes, clears, applies cooldowns/events, and owns side effects.
- decision: one `BotController` on the shared Player prefab is the non-local aim and intent owner. `[DefaultExecutionOrder(-200)]` lets it publish intent before `BallKick` at `-100` and ordinary fixed-step leaves. It writes root yaw plus clamped `Head.localRotation` in `FixedUpdate`; `PlayerLook` remains the mutually exclusive local-only writer.
- decision: `ParticipantState` remains the per-slot gate owner. All weapon/kick leaves receive the match/alive gate; device input/look receive it only for the local slot; `BotController` receives it only for non-local slots. Match freeze also pauses participant lifecycle timers without using global `Time.timeScale`.
- decision: difficulty is an enum selected and locked by `MatchController`; allies always receive Medium and all enemies receive the selected Low/Medium/High value. Pure static parameter profiles are code, not ScriptableObjects, so there are no new generated profile assets.
- decision: default profiles are playtest starting points: Low `(reaction 0.45s, decision 0.35s, jitter 0.12s, aim noise 7 degrees, prediction error 0.35)`; Medium `(0.22s, 0.20s, 0.06s, 3 degrees, 0.15)`; High `(0.10s, 0.12s, 0.03s, 1.5 degrees, 0.06)`. Explicit slot/decision/channel hashes provide deterministic samples; no `UnityEngine.Random` or hidden awareness differs by tier.
- decision: navigation is a scene-owned serialized directed graph plus deterministic A*. Nodes distinguish Floor, RampDeck, and GoalRecess; edges distinguish Walk, Ramp, Drop, and ShieldGate. Bots steer only along the current corridor and never direct-shortcut ledges. No NavMesh or runtime discovery is introduced.
- decision: the builder creates a three-lane floor graph at Z `-28/0/28` and X `-52/-12/0/12/52`, connects stable spawn/pickup/goal-mouth anchors, derives each ramp's low/high anchors from its canonical transform at local deck points `(0,0.25,-8)` and `(0,0.25,8)`, adds only validated high-to-floor drop edges, and gives each mouth/recess edge its exact enabled shield collider as a gate. Enabled shields make recess paths unavailable.
- decision: perception samples only serialized references. Opponent, ball, and pickup observations use a 75m, 130-degree LOS cone and expire after 1.5s when unseen. Pickup return time is remembered only after a bot witnesses available-to-unavailable transition; coordinated reset clears memory. Unseen `RespawnRemaining` is never read.
- decision: one coordinator per team owns role assignment. Living bots receive unique Attacker/Support/Defender roles where roster size permits; at least one of two-or-more living bots remains Defender. Re-evaluate every 0.5s, hold roles for 2.0s, require a 0.15 normalized score margin to switch, and break ties by slot ID.
- decision: football utility dominates combat. Own-goal emergency/defense and reachable scoring actions outrank support positioning, pickups, and opportunistic enemy damage. Yield shotgun within 12m to the local human who lacks one; yield health within 10m to a teammate at or below 30% health who is more injured.
- decision: combat uses constant-speed intercept plus deterministic difficulty error. Shotgun is eligible against a visible enemy within 16m or the ball within 20m; dash is eligible for a reachable ball/contact target within 2.2m; rocket is the default ranged action when its predicted line is clear and no ally is inside a 1.5m safety corridor. High-only rocket jump is an authored grounded vertical-route heuristic, never a ballistic solver.
- decision: weapon impulses that actually affect the ball call `BallMotor.RecordParticipantTouch(owner)` so rocket/shotgun bot ball control participates in the existing goal/own-goal attribution contract.
- decision: append `Setup=6` and `Paused=7`; never reorder existing match-state ordinals. Setup defaults to Medium and defers `BeginNewMatch`. Pause is allowed only from Playing, uses the existing match gameplay gate, preserves the clock and motion state, and resumes to Playing. Escape's existing cursor release triggers pause through observed `CursorCaptured`; no input-action asset change is required.
- decision: add `MovementLabBotPipeline.cs` for graph/composition constants instead of changing `MovementLabContractCatalog.cs`; this avoids coupling navigation data to the catalog's lighting fingerprint. Bump `SerializedContractVersion` `5 -> 6`, material-prefab contract `9 -> 10`, and gameplay-scene contract `14 -> 15`; keep manifest schema `8`.
- assumption: current `Compare-GeneratedYaml.ps1` reports `.meta`, PNG, and EXR paths as `NOT CHECKED`, and the source helper explicitly excludes the unfinished binary comparer. If the one production bake changes any comparator-unsupported authoritative binary, or if the required semantic Player prefab/scene change cannot satisfy the current canonical-equality gate, execution must stop at the generated-output gate and request separately authorized tooling/policy resolution; this plan does not silently relax that gate or absorb the excluded recovery work.
