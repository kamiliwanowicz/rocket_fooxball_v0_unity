## Objective

Replace the existing procedural world character and first-person kick leg in place with one coherent industrial cyborg design, re-author its animation set, and persist the result through the generated MovementLab pipeline. Completion means the new art reads like the concept from every gameplay angle, contains no foot-propulsion representation, the world kick reaches the gameplay contact pose at 0.10 seconds with a straight horizontal striking leg and tightly tucked support leg, the first-person kick matches it without clipping, existing movement/ball/collision contracts are unchanged, and clean committed Unity outputs pass independent review and exact semantic validation.

## Scope

- in: authoritative Blender generators and `.blend`/FBX outputs for `LowPolyCharacter` and `FpsKickRig`; world `Idle`, `Run`, `Jump`, `Fall`, `Land`, and `Kick`; first-person `Idle` and `Kick`; Generic-rig import settings; world/FPS Animator controllers; character PBR palette/material routing; team-tint selection; Player prefab composition; stage staleness; persisted validator coverage; generated prefab/controller/material/scene/manifest and conditionally affected lighting outputs

## Decisions

- assumption: the three figures in the concept are three poses of one cyborg, not separate character variants; all six participants continue to use the same Player prefab and team identity remains a runtime armor tint plus existing shape cue.
- decision: preserve `Tools/Blender/LowPolyCharacter.blend`, `Assets/_Game/Models/LowPolyCharacter.fbx`, `Tools/Blender/FpsKickRig.blend`, `Assets/_Game/Models/FpsKickRig.fbx`, both `.meta` files/GUIDs, the Generic rigs, required bone/action names, world scale `1.2`, FPS mount `(0.12,-0.42,0.30)`, and Blender `-Y` -> Unity `+Z` forward conversion.
- decision: the world silhouette uses a broad armored torso, asymmetric spiked shoulder cowl, recessed twin-lens camera pod, rear tank, bent exhaust stack, ball-tip antenna, exposed piston limbs/circular joints, plated forearms/articulated fists, and heavy ordinary boots. The exhaust and antenna are static/mechanical silhouette features only; no emitted smoke or propulsion is added.
- decision: retain four one-slot world renderers: `CharacterArmor` = team-painted outer armor, `CharacterBody` = gunmetal mechanisms, `CharacterHead` = worn tan tank/housings, `CharacterEye` = emissive red lenses. Retain one three-slot `FpsKickMesh` ordered armor/body/head so the first-person shin and boot use the same palette.
- decision: the FPS armor is intentionally the concept’s neutral worn olive `(0.29,0.31,0.20,1)`, not a team-identity signal. `FpsKickMesh` stays outside `PlayerPresentation` team tinting because the current runtime exposes renderer-wide rather than material-slot tinting; adding it would incorrectly recolor all three FPS material slots. The legacy `KickRed` Blender slot name remains only for importer compatibility; it maps to olive `CharacterRed`. No runtime tint API change is in scope.
- decision: preserve action names and existing non-kick ranges; change world Kick from frames `1..12` to `1..11`. Both kicks run at 30 fps, strike at frame 4 (`(4-1)/30 = 0.10s`), and finish at frame 11 (`0.333s`), matching `BallKickDefaults.DashContactStartDelay` exactly and `PlayerMotorDefaults.DashDuration` within one source frame.
- decision: the kick image governs legs only. The world Kick clip keys only the six leg bones; the striking right leg is straight/horizontal and the left leg folds beneath the pelvis. Torso, arms, head, weapon mount, and root continue from the locomotion layer rather than copying the photographed upper-body pose.
- decision: world animation uses a base locomotion layer plus an override kick layer. `BallKick.DashStarted` remains the sole accepted-kick visual trigger; no Animation Event, `KickSucceeded`, or gameplay delay is introduced.
- question: None
